## Run
- Setup: `just setup` (pnpm install). Dev: `just dev` (http://localhost:3000). Preview a production build: `just preview` (`pnpm build` then `pnpm start`).
- The one gate before a merge: `just check` = `pnpm lint`, `pnpm build`, then `tsc --noEmit` (after the build, because a fresh clone has no `next-env.d.ts` or `.next/types` until Next generates them). There is no test suite and no typecheck script, so `just test` is a stub.
- The card for tools and agents is `project.yaml`. No env files: the app reads no `process.env` anywhere.
- Built with Node 24 and pnpm 10.19; Vercel builds on Node 24.x. Next 16 needs Node 20.9 or newer.

## Layout
- Next.js 16 App Router, React 19, Tailwind v4, TypeScript. No CMS, no database, no client-side data fetching. Around 2,000 lines of source in total, so almost any change touches something documented below.
- `src/app/` routes (home, `privacy/`, `products/`, OG image, robots, sitemap) and `globals.css`; `src/components/` (home sections, `Analytics.tsx`); `src/content/` all page copy; `src/assets/` fonts; `public/` images.
- `docs/` is the working reference (architecture, design system, content and voice, operations, gotchas; `docs/reports/`). `README.md` is the GitHub landing page and deliberately shallow.
- `build-plan/` holds orchestrated builds.

## Rules that bite
These are invariants, not preferences. Each links to the file that explains it.
- pnpm only, never npm.
- **All copy lives in `src/content/`.** Section components hold no copy of their own, not even a heading. [content-and-voice.md](docs/content-and-voice.md)
- **Server components only.** There is no `"use client"` anywhere in this repo. Adding the first one is an architectural decision, not a detail. [architecture.md](docs/architecture.md)
- **Design tokens only.** Never an arbitrary colour; spacing comes from the scale. [design-system.md](docs/design-system.md)
- **Radius is `0` everywhere except the portrait, and there are no shadows at all.** The accent colour never covers more than about 2% of the page. [design-system.md](docs/design-system.md#the-visual-law)
- **Read [gotchas.md](docs/gotchas.md) before editing `src/app/globals.css`.** It contains a specificity trap that silently drops every heading to weight 400.
- **Em dashes are used sparingly in page copy.** Prefer commas, then parentheses. [content-and-voice.md](docs/content-and-voice.md#punctuation)
- **Every number on the page is a measured result from a shipped project**, and work is anonymized: no client names, logos or screenshots. [content-and-voice.md](docs/content-and-voice.md)
- **Comments here explain decisions, not syntax.** The existing prose comments are load-bearing documentation; several constraints exist only in them. Match that density rather than stripping it.
- **Every value lives in exactly one file.** A number, a token or a formula is stated once and linked to from anywhere else that needs it. `docs/gotchas.md` restates *rules* deliberately, so that the file stands alone as a pre-flight check, but never the numbers behind them.

## Safety
- **Pushing to `main` deploys to production** (Vercel git integration). There is no staging environment. [operations.md](docs/operations.md) Never run `just deploy` or push `main` without Robi.
- **This repo is public.** Never commit identifiers, `.vercel/`, or any `.env` file.
- Never print, copy or commit env files or tokens; a dev server binds 127.0.0.1 and is stopped before you finish.

## Definition of done
- Before handing work back: `just check` passes (`pnpm lint`, `npx tsc --noEmit`, `pnpm build`); the page change was seen working (`just dev` or `just preview`).
- One commit per change; the coding note and the project note's Log updated (coding-log skill).
